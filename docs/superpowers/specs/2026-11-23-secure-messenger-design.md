# Secure Messenger — согласованная спецификация

## Статус

Дизайн согласован пользователем. Этот файл фиксирует утверждённые решения; реализация разделена на четыре проверяемых приращения.

## Границы и приоритеты

- Закрытый круг, до 100 пользователей; приоритет — максимальная практическая безопасность. Абсолютное отсутствие уязвимостей не обещается.
- Регистрация по приглашению, email + пароль, обязательный уникальный ASCII username. Подтверждение и восстановление через email. SMS и телефонные номера исключены.
- Один активный device ID на аккаунт в MVP; account ID и device ID разделены для будущего multi-device.
- Поиск только по username. Адресная книга телефона не загружается.
- Сервер нужен для аккаунтов, публичных ключей, маршрутизации и офлайн-очередей. P2P не входит в MVP.
- Разработка на компьютере пользователя. Постоянный production-узел — выделенный Linux-хост или VPS; основной Windows-ПК не выставляется напрямую в интернет.
- Исходный код совместим с AGPLv3. Собственная криптография запрещена.
- Основной Android-телефон — POCO X5 Pro. Flip 4 проверяется на Flex Mode и восстановление состояния; полноценный внешний экран не требуется.
- Распространение MVP — подписанный APK. Магазины являются отдельным этапом без предположения о бесплатности.

## UX и адаптивность

Экраны: регистрация/вход/восстановление, подтверждение email, список чатов, поиск username, личный/групповой чат, safety number, профиль и настройки.

Компактное окно использует одну панель. Достаточно широкое окно — list/detail. Flex Mode размещает контент над шарниром, ввод под ним. WindowSizeClass определяет пространство, FoldingFeature — шарнир. Выбранный чат, черновики, прокрутка, загрузки, outbox и запись голоса переживают пересоздание UI; черновики переживают и завершение процесса.

## Сервер

Kotlin + Ktor, PostgreSQL, Caddy/Nginx на постоянном узле, локальное ciphertext-файловое хранилище за интерфейсом object storage. Для 100 пользователей начинается один модульный узел без Redis/Kafka/Kubernetes.

Сервер хранит account/session/device records, публичные prekeys, временные ciphertext-очереди, group membership и одноразовые token hashes. Приватные ключи, plaintext сообщений, файловые ключи, plaintext паролей и токенов не хранятся.

Пароли хешируются Argon2id. Refresh tokens ротируются и хранятся по хешу. Email/invite tokens одноразовые, с TTL, ограничением попыток и HMAC для коротких кодов. Recovery отвечает одинаково независимо от наличия email. Сброс пароля отзывает сессии.

Сообщения имеют стабильный message ID, TTL и idempotent enqueue. Получение подтверждается, после чего временные записи удаляются. Prekeys выдаются атомарно не более одного раза. Сервер видит минимально необходимые метаданные, но не заявляется их отсутствие.

## Android и E2EE

Compose, Material 3 Adaptive, Jetpack WindowManager, ViewModel/SavedStateHandle, Room/SQLCipher, DataStore, Hilt, Coroutines/Flow, OkHttp HTTPS/WSS, WorkManager, Media3 и Photo Picker.

Официальные совместимые libsignal-android/libsignal-client фиксируются одной версией. Identity и приватные ключи создаются и остаются на устройстве; Android Keystore защищает локальные обёртки. PQXDH/Double Ratchet используются только через поддерживаемый API выбранной версии.

Safety numbers/QR доступны пользователю. При смене ключа отправка приостанавливается до явного подтверждения. Восстановление пароля не восстанавливает старую E2EE-историю на новом устройстве.

Группы MVP используют pairwise Signal-шифрование. Медиа шифруются одноразовым файловым ключом; ключ и метаданные передаются внутри E2EE-сообщения. Сервер не создаёт превью и не перекодирует медиа. FCM необязателен и содержит только обобщённое событие; APK работает без него через WSS fallback.

## Приращения и приёмка

1. Приглашения, регистрация, email verification/recovery, сессии, username search, адаптивный UI-каркас. Незашифрованных пользовательских сообщений нет.
2. Личные E2EE-тексты, outbox, receipts, safety numbers и MITM-тесты.
3. Pairwise-E2EE группы, фото/видео/файлы/стикеры/голосовые, encrypted upload/download.
4. Push/fallback, сетевая надёжность, Flip/POCO polish, нагрузочные и security checks, release APK.

После каждого приращения: `assembleDebug`, unit/integration tests, `adb install`, реальный сценарий и проверка logcat. Затем git commit. Dev Mailpit разрешён только как явно dev-only SMTP и не считается production email delivery.
